# Alternate transport — the escape hatch beside the primary API contract

Most endpoints are described entirely by the primary API-contract mechanism. Occasionally a route needs something that mechanism cannot express — a streaming binary body with its own entity-size limit is the recurring example — and that one route is implemented directly against a lower-level HTTP library instead, bypassing the contract entirely. This document defines **project-agnostic conventions** for that alternate-transport escape hatch, written around [Tapir](https://tapir.softwaremill.com/) (`sttp.tapir`, this codebase's concrete choice for its one streaming organization-logo upload endpoint) but applicable to any framework used the same way: as a narrow, deliberate exception for the handful of routes the primary contract can't cover.

## Scope

This document owns the conventions a new alternate-transport endpoint must follow so it stays consistent with the primary contract it sits beside, without being generated by it:

- **file split** — where the shared transport helpers live versus the per-feature endpoint definitions;
- **a parallel, not shared, error model** — the alternate transport defines its own error enum mirroring the primary contract's error taxonomy case-by-case, and the discipline needed to keep the two in sync by hand;
- **hand-mirrored security** — since the central middleware does not cover this transport, each endpoint wires its own auth/role checks that must replicate the middleware's rules;
- **swagger/OpenAPI parity** — how a hand-built spec for these routes is generated and kept visible alongside the primary contract's generated docs, including mount-order pitfalls;
- **transport-specific entity-size limits** — why this transport needs its own size ceiling, separate from the primary contract's, and how to keep it in sync with config;
- **naming** — case and suffix conventions for the alternate error model's types and constants.

This document **excludes**, and cross-links instead:

- the primary API-contract mechanism itself, and how it declares auth/role requirements on a normal operation → [smithy-new.md](smithy-new.md);
- the central middleware whose auth/onboard-stage/role checks this transport must replicate by hand (since the middleware does not run in front of it) → [../middleware-new.md](../middleware-new.md);
- general Scala/type naming conventions (case, acronym policy, avoiding abbreviation) → [scala-new.md](scala-new.md); this document only adds the alternate-transport-specific naming on top.

See [../features/files-management.md § Why Tapir](../features/files-management.md#why-tapir-and-not-smithy) for a concrete write-up of why one particular endpoint needed this escape hatch instead of the primary contract — that rationale is feature-specific and lives there, not here.

## File layout

Split the alternate transport's code into two kinds of files, and give every new endpoint the same split:

- a **shared helpers file** — the security base (bearer + organization-header wiring), error-rendering/decode-failure handling, a swagger role-description helper, and any shared type aliases or server options that every endpoint on this transport reuses;
- a **per-feature endpoint file** — the actual endpoint definitions plus the wiring function that resolves services and builds the runnable server endpoints.

Concretely in this codebase: `tapir/tapir.scala` holds the shared helpers (`securedEndpoint`, `decodeFailureHandler`/`tapirServerErrorOut`, `requiredOrganizationRolesDescription`, the `TapirTask`/`TapirEndpoints` aliases, `tapirServerOptions`); `tapir/FileServiceEndpoints.scala` holds the per-feature endpoints (`uploadOrganizationLogoPostEndpoint`, `docsEndpoint`) and the ZIO wiring function (`allRoutesAndDocsEndpoints`).

## Error model — parallel to the primary contract's, not shared with it

The alternate transport defines **its own error enum**, mirroring the primary contract's error taxonomy one case at a time rather than reusing its generated error types. Concretely: `TapirServerError` is a 7-case enum (`BadRequestError`, `UnauthorizedError`, `ForbiddenError`, `NotFoundError`, `ConflictError`, `InternalServerError`, `ServiceUnavailableError`), each carrying `code`/`message`/`schemaName`; a dedicated mapping function (`HttpErrorHandler.errorResponseHandlerTapir`) turns a domain service error into this enum, mirroring the primary contract's own error-mapping function case-by-case.

**Whenever a domain error subtype is added or re-homed, update both error handlers together.** The primary contract's handler gets a compile-time nudge — a generated operation's declared error list won't compile if a case is missed — but the alternate transport's handler is a plain `match` with no such check. A missed case there is a silent runtime gap, not a build failure, so it needs to be caught by discipline (and ideally a test), not the compiler.

## Security is hand-wired to mirror the middleware

Routes on this transport are **not** covered by the central middleware (see [../middleware-new.md](../middleware-new.md)): each endpoint wires its own auth directly (`zServerSecurityLogic(authorizationService.auth(...))`), using the shared security base's typed security inputs (bearer token, organization-ID header). Concretely, `uploadOrganizationLogoPostEndpoint` calls `authorizationService.auth` with `requiresCompletedOnboardStage = true` and an explicit allowed-roles set — replicating exactly what a middleware-gated operation with the equivalent onboard-stage and role annotations gets automatically.

**When a middleware rule changes, update every alternate-transport endpoint's security logic by hand to match.** This is the transport's single biggest correctness trap: nothing enforces that the hand-wired checks stay in sync with the middleware's rules, so a middleware change silently stops applying to these routes unless someone remembers to mirror it.

## Swagger/OpenAPI integration

The primary contract's codegen does not produce an OpenAPI spec for routes on this alternate transport, so the transport must generate its own (e.g. via `OpenAPIDocsInterpreter().toOpenAPI(...)`), served from a plain docs endpoint that mimics the primary contract's generated doc path (concretely, `GET /docs/specs/<namespace>.<ShapeName>.json`, implemented as `docsEndpoint`). The alternate-transport service is still listed in the shared Swagger UI alongside the primary contract's services, by passing its doc ID into the same route-mounting call the primary contract's docs use.

**This alternate-transport docs route must be mounted before the primary contract's swagger routes** in the app's route wiring — otherwise the primary contract's routing intercepts the path first and 500s trying to load a classpath spec that doesn't exist there. Concretely, this ordering constraint is called out with an `IMPORTANT: Ordering matters` comment at the mount site (`HttpApp.scala`, in `externalDocsRoutes`).

Since the role check for one of these endpoints runs inside its hand-wired security logic — invisible to OpenAPI generation — add an explicit description to the endpoint listing the same roles the security logic enforces, using a shared helper. The helper renders the same required-roles marker used in the primary contract's operation doc comments (see [smithy-new.md](smithy-new.md)), so the two sets of docs can't drift apart in how they describe a role requirement.

## Schema/codec quirk — one named schema per error variant

The alternate transport's error enum needs **one explicitly named schema per case**, so each status code renders as a distinct OpenAPI component instead of collapsing into one generic error shape. Concretely, `tapirServerErrorSchemas` (in `json/json.scala`) names each case's schema after the equivalent generated response-content name from the primary contract (e.g. `BadRequestResponseContent`), so both sets of swagger docs expose consistent component names for the same logical error. A separate fallback schema (named `"ServerError"`) covers paths — like the decode-failure handler — where the specific variant isn't known ahead of time. The codec should round-trip through the stable `code` field, not the display name, and should fail loudly on an unrecognized code rather than silently defaulting to some case.

## Entity size limits are transport-specific

Configure a distinct maximum entity size for the alternate transport's routes, separate from the primary contract's limit — concretely, `HttpApp.scala` sets `SmithyMaxEntitySize` (2 MB) for the primary contract's routes and a separate, larger `TapirMaxEntitySize` (20 MB) for Tapir routes, since this transport carries the logo upload.

**Keep the transport's max-entity-size constant in sync with its corresponding config value** (concretely, `file-service.max-organization-logo-bytes`) — the two are not derived from one another, so a config change that isn't mirrored in the transport's limit leaves the two silently disagreeing.

## Naming

Name the alternate transport's error cases and codes the same way the primary contract's naming already establishes a pattern for: `PascalCase` with an `Error` suffix for the case (`BadRequestError`, `ConflictError`), and `SCREAMING_SNAKE_CASE` for the wire code (`BAD_REQUEST_ERROR`). See [scala-new.md § Case and grammatical form](scala-new.md#case-and-grammatical-form) for the general case-and-naming rules this specializes.
